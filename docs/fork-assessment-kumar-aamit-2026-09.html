Date: 2026-09-09 · Fork: kumar-aamit/DemoBot main @ 5918842 (7 commits over merge-base c8310b7, PR #65, v4.8.1) · Target: mayeack/DemoBot main @ 9bc7aa6 (PR #68, v4.9.0) · Fork author: Amit Kumar (amkum2@cisco.com) · GitHub compare: diverged, ahead 7 / behind 5, no PR in either direction · Outcome: 3 commits kept, 1 kept in part, 2 reworked, 1 rejected; lands as three PRs and ships as 4.10.0.

Summary

  • What the fork set out to do: run the app on an on-prem OpenShift cluster behind a Cisco AI Defense gateway, drive it from a remote Nemotron served through Ray Serve, keep long chat turns alive through proxies, and rebrand the product from DemoBot to PseudoCo Assistant for that customer.
  • What is taken as-is: the SSE heartbeat (5918842) and the OpenShift routing decision — a remote NIM is reached through provider=openai with OPENAI_REASONING=False, because provider=nvidia is loopback-only by design (backend/nvidia_nim.py). The openai_reasoning flag from 30e8336 is kept and completed (Settings field, .env.example, tests, and a cache-key fix).
  • What is reworked: the OpenShift manifests (build from the upstream repo with the shared Containerfile, no duplicate Dockerfile, the 3,119-line CA snapshot replaced by the 2-cert ingress chain plus a ca-bundle init container) and the rename, which the fork did as a blanket search-and-replace across 148 files. That sed renamed ~40 load-bearing identifiers and corrupted addresses of things outside the repo (REPO_URL="https://github.com/mayeack/PseudoCo Assistant.git" in the EC2 bootstrap, the /Applications/DemoBot and ~/DemoBot checkout paths, ~/.ssh/demobot_ec2). The rename is redone as a scripted, re-runnable pass with an explicit exclusion list — the user chose the full identifier rename, so every external object it forces to be re-pointed is listed in §7.
  • What is rejected: de-registering the NVIDIA AI Virtual Assistant blueprint (7 failures in tests/test_nvidia_blueprint.py; the parity matrix silently dropped from two blueprints to one), hard-coding hidden on two Demo Controls cards and disabling NemoClaw polling (replaced by a proper per-card visibility panel on the Settings page), deleting openclaw/Containerfile (an accident of the endpoint agent on the maintainer's Mac), and renaming the blueprint keys as governance identity.
  • Why not git merge: a dry-run merge conflicts in 21 files, all rebrand-versus-PR #66/#68, and the three dangerous hunks (blueprint de-registration, module rename, Containerfile deletion) would have auto-merged silently.

5. Strategy

Chosen: fresh branches off main; git cherry-pick -x for the verbatim commit (SSE heartbeat, author Amit Kumar), a partial pick for the reasoning flag (author preserved), fresh commits with Co-authored-by trailers for the reworked OpenShift material, and a scripted rename generated on the merged tree. History carries only the accepted content; the fork commits are referenced from each commit body.

Rejected: merging the fork branch and resolving the 21 conflicts by hand — it would carry the blanket sed and the four regressions into main and still need a second rename pass for text PR #66/#68 added after the fork.

7. Operator checklist after PR-B (nothing here is automated)

  1. Per box, decide the telemetry identity. The Mac's .env pins OTEL_SERVICE_NAME=demobot-v3, deployment.environment=demobot-local, SPLUNK_AO_PROJECT=DemoBot, SPLUNK_AO_AGENT_STREAM=DemoBot; those keys win over the new code defaults. Remove or change them per box to move that box to the new names.
  2. Splunk Observability Cloud: re-create the two APM detectors on the new service with scripts/observability/create_apm_detectors.py (the old ones stay on demobot-v3 until deleted); update dashboards that filter on demobot.* span attributes or the old environment names.
  3. Splunk Enterprise (gen_ai:json): searches and dashboards keyed on service_name, deployment_id, workflow_name, blueprint need the new values from the cut-over time; historical events keep the old ones.
  4. Agent Control: re-register the agent Done 2026-09-09. scripts/demo/register_agent_control.py created agent pseudoco-assistant-agent (step pseudoco-assistant-llm) and attached controls 259/263/576; demobot-agent is left in place. Until this ran, GET /api/v1/agents/pseudoco-assistant-agent/controls returned 404 and the guardrail loaded no definitions at all, so it failed open on every turn. The three controls still carry their original DemoBot-block-* names — renaming them to PseudoCoAssistant-block-* is outstanding and needs a console-side PATCH /api/v1/controls/{id}. Enforcement is partial: 263 (output PII) blocks in-process, while 576 and 259 still fail their client-side Luna scorers (see the project notes on the org's missing runtime-token grant).
  5. Agent Observability: keep SPLUNK_AO_PROJECT/SPLUNK_AO_AGENT_STREAM pinned where the existing DemoBot project should keep receiving traces; unset them where a new project is wanted.
  6. AI Defense: src_app changes; nothing to configure, but filters on the old value stop matching.
  7. OpenClaw / NemoClaw: rebuild the images (run-openclaw.sh, run-nemoclaw.sh); the plugin id, install path, build args and the network-policy preset all carry the new names. The decoy workspace and gateway state dirs are excluded from the rename and stay where they are.
  8. EC2: fresh bootstraps install pseudoco-assistant- units; re-running the bootstrap on an existing box stops, disables and removes the legacy demobot- units first. Replica scripts resolve whichever app unit is installed.
  9. OpenShift: the manifests in PR-A already use the new names; nothing changes at PR-B.
